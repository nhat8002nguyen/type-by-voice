# Styled macOS DMG Installer Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `TypeByVoice.dmg` open as a designed drag-to-install window — app icon on the left, `Applications` on the right, large icons, an arrow between them — instead of the unstyled window it opens as today.

**Architecture:** `package-dmg.sh` builds the writable intermediate with `hdiutil create -format UDRW`, mounts it, drops a HiDPI arrow backdrop into a hidden `.background/` folder, drives Finder once via AppleScript to record view settings (icon size, window bounds, background picture, item positions) into the volume's `.DS_Store`, then re-compresses to `UDZO`. Finder is needed for exactly one step because the view settings live in a `Bud1` container that is impractical to author by hand; everything else is the existing staging/plist/signing flow. The arrow art is generated by a committed Swift/CoreGraphics script rather than stored as a hand-made binary.

**Tech Stack:** zsh, `hdiutil`, `tiffutil`, `osascript`/`osacompile`, AppleScript, Swift + CoreGraphics (generator only), `sips` (verification only). No Homebrew, no pip, no new dependencies.

**Spec:** Informal request with a reference screenshot (Google Drive's installer) plus [2026-09-28-macos-unsigned-dmg.md](./2026-09-28-macos-unsigned-dmg.md), which this plan amends. "Regular drag I face" is read as: the app's drag-to-install window should look like the standard styled one users are used to.

## Global Constraints

- **No new dependencies.** Everything must run with tools already on the machine: `hdiutil`, `diskutil`, `tiffutil`, `sips`, `osascript`, `osacompile`, `swift`, `strings`, `codesign` (all verified present on macOS 27.0.1).
- **`hdiutil create … -format UDRW` is mandatory** for the writable intermediate. `diskutil image create from --format` accepts only `ASIF RAW UDRO UDSB UDZO ULFO ULMO` (verified: `diskutil help image create from`) — there is no read-write format there, so the modern API cannot replace this step.
- `hdiutil` prints `WARNING: … is deprecated` on this OS. Keep using it, and leave a comment naming `diskutil image create from <src> --format UDZO <dst>` as the drop-in for the final compression (verified working).
- Shipped image keeps `-volname "TypeByVoice"` and `-format UDZO`. `macos/.env` sourcing, the `Info.plist` `TBV_API_URL`/`TBV_DICTATE_URL` bake, ad-hoc re-signing, and `publish-dmg-release.sh` are untouched.
- **Layout metrics (pinned):** window frame 540×422 — 540×400 of *content* plus the 22pt Finder title bar (see the clipping note below); `icon size` 128; `text size` 14; backdrop canvas 540×400; arrow 72×52 centred at `(270, 212)`. Icon positions are `{contentWidth / 2 ∓ iconOffsetX, 212}` — symmetric about the window's centre and on the arrow's line — with `iconOffsetX = 124` (64 half-icon + 36 half-arrow + 24 clearance), i.e. `{146, 212}` and `{394, 212}`.
- **Finder's item `position` is the item's *centre*, not its frame's top-left corner.** Measured on a real build: asking for `{116, 148}` put the icon's centre there. This plan originally assumed the opposite and shipped a pair 50pt off-centre with the arrow overlapping the Applications icon, so treat any "position + iconSize/2" arithmetic as wrong.
- **Finder clips a backdrop picture that is taller than the content view from the top.** A 400pt canvas inside a 400pt *frame* therefore loses the title bar's height off the top and lifts the arrow by that much — measured 22.2pt high on a real build whose title bar was 22pt. Size the frame to content + title bar, as above.
- **Backdrop is transparent**: `panelAlpha = 0` — no opaque or tinted canvas, so the system window colour shows through in both Light and Dark Mode.
- Never commit `macos/dist/`, the intermediate `*-rw.dmg`, or any `.DS_Store`.
- **Do not stage** `macos/TypeByVoice/TypeByVoiceApp.swift`, `macos/Scripts/make-menubar-icon.swift`, or `macos/TypeByVoice/Assets.xcassets/MenuBarIcon.imageset/` — unrelated in-flight work is sitting uncommitted on this branch. Commit by explicit path only.

## Review Focus

The five input classes / failure modes this request implies that no task's automated test covers, most likely first:

1. **Label legibility over a transparent background picture.** Finder picks the icon-label colour from the background *picture*; a mostly-transparent picture can make it choose white labels, which are invisible on a light window. Expected: labels readable in both Light and Dark Mode.
2. **Retina arrow scale.** Finder must draw the HiDPI TIFF's 1080×800 representation at 540×400, not stretch it. Expected: arrow ≈72 pt wide and crisp, not 144 pt.
3. **Stale same-named volumes.** This machine currently has `/Volumes/TypeByVoice`, `/Volumes/TypeByVoice 1` and `/Volumes/TypeByVoice 2` mounted (all read-only `Disk Image` mounts). The AppleScript addresses the volume *by name*, so a pre-existing mount receives the layout instead of the image just built. Expected: the build self-heals, and the shipped DMG shows the layout on first open.
4. **No Automation permission, or a sandboxed shell.** Verified here: any AppleEvent to Finder from a sandboxed shell fails with `Finder got an error: A privilege violation occurred. (-10004)`. Expected: a loud failure that names the fix — never a silently unstyled DMG, and never a half-built artifact left behind.
5. **`position` semantics.** Finder's item `position` is the origin (top-left) of the item's frame — icon plus label — not its centre. Expected: icons land where the constants intend, on the arrow's centre line.

Each line's test is added to the task that owns the code: 1 → Task 4 step 5, 2 → Task 2 (gate), 3 → Task 4 step 1 + 3, 4 → Task 3 step 3, 5 → Task 2 (gate).

### Task 2: `check-dmg-layout.sh` — the gate

**Files:**
- Create: `macos/Scripts/check-dmg-layout.sh`

**Interfaces:**
- Consumes: a DMG path as `$1`; optional `--structural-only`.
- Produces: exit 0 when the DMG is styled, exit 1 with one `FAIL: …` line per broken expectation. Prints `PASS: …` for each satisfied one. Task 4 must make this pass.

Write the check first and watch it fail on today's artifact — that failure *is* the bug report for this whole plan.

- [ ] **Step 1: Write `macos/Scripts/check-dmg-layout.sh`**

`#!/bin/zsh` + `set -uo pipefail` (do **not** use `set -e`: the script must run every assertion and report all failures). Mount read-only into a fresh temp dir and always detach:

```zsh
# (superseded by the fix pass — see the note below the snippet)
for stale in /Volumes/$VOLUME_NAME*(N); do
  hdiutil detach "$stale" >/dev/null 2>&1 || rmdir "$stale" 2>/dev/null || true
done
MNT="/Volumes/$VOLUME_NAME"
hdiutil attach "$DMG" -nobrowse -noautoopen -readonly -mountpoint "$MNT" >/dev/null
trap 'hdiutil detach "$MNT" -force >/dev/null 2>&1 || true; rmdir "$MNT" 2>/dev/null || true' EXIT
```

Address everything through `$MNT`. **Mount at `/Volumes/TypeByVoice` and detach every
same-named volume first**, because the read-back in step 1 addresses the volume *by
name* (Finder has no reliable mountpoint-based disk reference). With two volumes named
`TypeByVoice` mounted — the kernel suffixes the mount path `TypeByVoice 1`,
`TypeByVoice 2` — Finder can resolve `disk "TypeByVoice"` to the wrong one, and the
gate would pass or fail against an older DMG. Measured on the machine this was written
on: three such volumes were mounted, and matching the exact path alone covered one.

Structural assertions (run always):

1. `$MNT/TypeByVoice.app` is a directory and `$MNT/Applications` is a symlink resolving to `/Applications`.
2. `$MNT/.DS_Store` exists and is larger than 0 bytes.
3. `$MNT/.background/dmg-background.tiff` exists and `tiffutil -info` reports exactly two images at 540×400 and 1080×800 — this is the Retina guard (Review Focus 2). If the TIFF is absent, accept `.background/dmg-background.png` at 540×400 instead: that is the fallback Task 4 Step 5 documents, and the gate must not fail a DMG produced by following the plan. (Filter `sips`'s output to its own `pixelWidth:`/`pixelHeight:` lines before extracting digits — it prints the file path first, and the path contains digits.)
4. The baked endpoints survived: `plutil -extract TBV_API_URL raw "$MNT/TypeByVoice.app/Contents/Info.plist"` and the same for `TBV_DICTATE_URL` both print a non-empty value.

Semantic assertions (skipped when `--structural-only` is passed), by reading the layout back out of a *fresh* mount:

```zsh
READBACK="$(osascript -e 'on run a
  tell application "Finder" to tell disk (item 1 of a)
    set v to icon view options of container window
    set p1 to position of item "TypeByVoice.app" of container window
    set p2 to position of item "Applications" of container window
    set b to bounds of container window
    return ((icon size of v) as text) & "|" & ((arrangement of v) as text) & "|" & (((background picture of v) is missing value) as text) & "|" & ((item 1 of p1) as text) & "," & ((item 2 of p1) as text) & "|" & ((item 1 of p2) as text) & "," & ((item 2 of p2) as text) & "|" & (((item 3 of b) - (item 1 of b)) as text) & "x" & (((item 4 of b) - (item 2 of b)) as text)
  end tell
end run' "TypeByVoice")"
```

Open the window before reading it — `container window` of a disk Finder has never opened is
`missing value` — which is why this tier briefly shows the volume's Finder window.

Assert on that string: `icon size` is `128`, `arrangement` is `not arranged`, `background picture … is missing value` is `false`, the window is `540x400` (one of the four original complaints was that the window was too large, so it is asserted too), `p1`'s x < `p2`'s x — the app left of Applications, the exact complaint (Review Focus 5) — **the pair's midpoint is within `POSITION_TOLERANCE` of the window's centre**, and **both icons' y are within `POSITION_TOLERANCE` of `212`**, the arrow's line. Those last two matter: the app-left-of-Applications check alone passed on the first shipped attempt, whose pair sat 50pt off-centre with the arrow overlapping the Applications icon and both icons 64pt above the arrow. Print the measured values in each failure message so the numbers can be read off the output. Print a clear `FAIL: app icon is not left of Applications (got …)` when it inverts.

Exits non-zero at the end if anything failed, summarising `n assertion(s) failed`.

### Task 3: `dmg-layout.applescript` — Finder view settings

**Files:**
- Create: `macos/Scripts/dmg-layout.applescript`

**Interfaces:**
- Consumes: `argv` — exactly one item, the mounted volume's name (`TypeByVoice`).
- Produces: the volume's `.DS_Store` view settings, and exit status 0. Non-zero (with a usage line for the empty-argv case, or a Finder error for a denied `-10004` / absent volume) otherwise. Task 4 calls it and reports the outcome.

- [ ] **Step 1: Write `macos/Scripts/dmg-layout.applescript`**

`on run argv` with a guard first, so a misuse fails before Finder is touched — and so it stays testable without Automation:

```applescript
on run argv
	if (count of argv) < 1 then error "usage: osascript dmg-layout.applescript <volumeName>" number 2
	set volName to item 1 of argv
	...
	return "ok"
end run
```

Constants at the top of the `run` handler, matching Global Constraints: `contentWidth` 540, `contentHeight` 400 and `titleBarHeight` 22, giving `windowBounds` `{400, 100, 940, 522}`, `icon size` 128, `text size` 14, `iconCentreY` 212, and `iconOffsetX` 124. Positions are `{contentWidth / 2 - iconOffsetX, iconCentreY}` and `{contentWidth / 2 + iconOffsetX, iconCentreY}` — derived rather than written as literals, so the pair stays balanced about the window centre if the width changes. Background file `".background:dmg-background.tiff"`.

Inside `tell application "Finder"` / `tell disk volName`: `open`; `set current view of container window to icon view`; `set toolbar visible of container window to false`; `set statusbar visible of container window to false`; `set bounds of container window to …`; then on `the icon view options of container window` set `arrangement` to `not arranged` (before the positions — auto-arrange overwrites them), `icon size`, `text size`, and `background picture`; then `set position of item "TypeByVoice.app" of container window to …` and the same for `"Applications"`; then `update without registering applications`, `delay 2` (Finder writes `.DS_Store` lazily), and `close`.

Use the volume-relative HFS-style path for the background (`file ".background:dmg-background.tiff"`): the alias Finder stores has to survive remounting at `/Volumes/TypeByVoice` by whoever downloads the DMG, so it must not point at a build-time temp path.

- [ ] **Step 1: Add the layout phase**

New constants near the existing `STAGE`/`APP_SRC` block:

```zsh
VOLUME_NAME="TypeByVoice"
MOUNT_POINT="/Volumes/$VOLUME_NAME"
INSTALLER_DIR="$MACOS_ROOT/Installer"
BG_BASE="$INSTALLER_DIR/dmg-background"
RW_DMG="$DIST_DIR/.TypeByVoice-rw.dmg"
```

Replace the tail (`rm -f "$DMG_PATH"` / `hdiutil create -srcfolder … -format UDZO`) with:

```zsh
# Layout needs Finder, which needs this process to be allowed to send AppleEvents.
# A sandboxed or agent-run shell cannot: it fails with -10004.
if ! osascript -e 'tell application "Finder" to get name of startup disk' >/dev/null 2>&1; then
  echo "error: cannot control Finder (AppleEvents refused, -10004)." >&2
  echo "  run this script from a normal Terminal window, and allow the" >&2
  echo "  \"... wants access to control Finder\" prompt" >&2
  echo "  (System Settings > Privacy & Security > Automation)." >&2
  exit 1
fi

for f in "$BG_BASE.png" "$BG_BASE@2x.png"; do
  [[ -f "$f" ]] || { echo "error: missing $f — run: swift macos/Scripts/make-dmg-background.swift" >&2; exit 1; }
done

TIFF_DIR="$(mktemp -d "${TMPDIR:-/tmp}/tbv-dmg-bg.XXXXXX")"
trap 'hdiutil detach "$MOUNT_POINT" -force >/dev/null 2>&1 || true; rm -rf "$TIFF_DIR" "$STAGE" "$RW_DMG"' EXIT

# HiDPI TIFF so Finder draws the arrow crisply on Retina instead of upscaling the 1x PNG.
tiffutil -cathidpicheck "$BG_BASE.png" "$BG_BASE@2x.png" -out "$TIFF_DIR/dmg-background.tiff" >/dev/null

# The layout script addresses the volume by name, so a stale mount of the same name
# would take the layout instead of this build (this machine had three of them).
while [[ -d "$MOUNT_POINT" ]]; do
  echo "==> Detaching stale mount at $MOUNT_POINT"
  hdiutil detach "$MOUNT_POINT" >/dev/null 2>&1 || { rmdir "$MOUNT_POINT" 2>/dev/null || break; }
done

rm -f "$RW_DMG" "$DMG_PATH"
echo "==> Creating writable image"
hdiutil create -volname "$VOLUME_NAME" -srcfolder "$STAGE" -ov -format UDRW "$RW_DMG" >/dev/null

echo "==> Mounting and applying layout"
hdiutil attach "$RW_DMG" -nobrowse -noautoopen -readwrite -mountpoint "$MOUNT_POINT" >/dev/null
mkdir -p "$MOUNT_POINT/.background"
cp "$TIFF_DIR/dmg-background.tiff" "$MOUNT_POINT/.background/dmg-background.tiff"
osascript "$MACOS_ROOT/Scripts/dmg-layout.applescript" "$VOLUME_NAME"
sync && sleep 2   # Finder writes .DS_Store lazily; do not detach before it lands
hdiutil detach "$MOUNT_POINT" >/dev/null

echo "==> Compressing → $DMG_PATH"
hdiutil convert "$RW_DMG" -format UDZO -imagekey zlib-level=9 -o "$DMG_PATH" >/dev/null
```

Keep a comment on the last line noting `diskutil image create from "$RW_DMG" --format UDZO "$DMG_PATH"` is the non-deprecated equivalent, and on the `hdiutil create` line noting that `-format UDRW` has no `diskutil` equivalent, which is why `hdiutil` stays. The `EXIT` trap replaces the old trailing `rm -rf "$STAGE"` and guarantees no mounted volume or intermediate image survives a failed run (Review Focus 4).

# TypeByVoice macOS client

Menu-bar dictation client for macOS 13+. Speaks the shared dictation v1 protocol
over WebSocket, encodes mic audio as Ogg Opus, and inserts the final transcript
via clipboard paste.

## Build & test

```bash
cd macos
xcodebuild test -scheme TypeByVoice -destination 'platform=macOS'
```

### Build and run (Debug)

Builds, resets Accessibility TCC for the ad-hoc-signed binary, and launches
against the local backend (`:3000` by default):

```bash
./macos/Scripts/build-and-run.sh
```

After each Debug build, re-enable **TypeByVoice** in  
System Settings → Privacy & Security → Accessibility.

### Run current build

Launch the existing Debug app without rebuilding:

```bash
./macos/Scripts/run.sh
```

Override API endpoints with `TBV_API_URL` / `TBV_DICTATE_URL` if needed.

### Prod / shared endpoints (`.env`)

```bash
cp macos/.env.example macos/.env   # gitignored — edit URLs there
./macos/Scripts/build-and-run-prod.sh   # or run-prod.sh
```

`build-and-run-prod.sh` / `run-prod.sh` load `macos/.env` (no hardcoded hosts).

## Share (unsigned DMG)

1. Ensure `macos/.env` has `TBV_API_URL` / `TBV_DICTATE_URL`.
2. Package:

```bash
./macos/Scripts/package-dmg.sh
# → macos/dist/TypeByVoice-<version>+<build>.dmg
```

Endpoints are baked from `.env` into the app Info.plist at package time (not hardcoded in source).

The packaged window is the designed drag-to-install one: 540×400, 128 pt icons,
the app on the left and the `Applications` alias on the right, with a grey arrow
backdrop between them. `macos/Installer/dmg-background.png` is generated by
`swift macos/Scripts/make-dmg-background.swift`.

Applying that layout means driving **Finder** once, to record the view settings
in the volume's `.DS_Store`, so:

- Run package-dmg.sh from a normal Terminal window. The first run asks
  *"... wants access to control Finder"* — allow it (or grant it later under
  System Settings → Privacy & Security → Automation). A sandboxed or agent-run
  shell is refused with `a privilege violation occurred. (-10004)`, and the
  script stops with that message before the build rather than producing an
  unstyled DMG.
- It detaches any existing `/Volumes/TypeByVoice*` first, because the layout is
  applied by volume name.

Verify a built DMG, and re-tune the window (icon size and positions in
`macos/Scripts/dmg-layout.applescript`, the arrow in
`macos/Scripts/make-dmg-background.swift`):

```bash
./macos/Scripts/check-dmg-layout.sh macos/dist/TypeByVoice-<version>+<build>.dmg
# --structural-only skips the assertions that need Finder automation
# --mount-point DIR mounts elsewhere when /Volumes is not writable (CI or a
#   sandboxed shell), which also means the Finder read-back is skipped
```

### Publish public download link

Uploads go to the **public** repo [`type-by-voice-releases`](https://github.com/nhat8002nguyen/type-by-voice-releases) (anonymous downloads while this app repo stays private):

```bash
./macos/Scripts/package-dmg.sh
./macos/Scripts/publish-dmg-release.sh
# Release tag [macos-v1.0.1+1] (Enter to accept):
# prints https://github.com/nhat8002nguyen/type-by-voice-releases/releases/download/macos-v…/TypeByVoice-….dmg
```

`publish-dmg-release.sh` always prompts on stdin for the release tag:

- **Enter / blank** → publishes the suggested tag. It is the DMG's own
  `<version>+<build>` when that tag is free and newest, otherwise the patch after
  the highest tag already on the release repo (`macos-v1.0.0+1` taken → `macos-v1.0.1+1`).
- **Typed value** → used as-is, with or without the `macos-v` prefix
  (`1.0.5` → `macos-v1.0.5`). A tag that already exists locally fails before anything is uploaded.

The uploaded asset is renamed to the chosen tag, so the tag, file name, and URL stay
consistent. If the chosen tag differs from the DMG's built version, the script warns
you to bump `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` and re-run `package-dmg.sh`.
It exits with an error when stdin is closed (no TTY), so pipe a tag or empty line if you
ever script it.

Override destination with `TBV_RELEASE_REPO=owner/name` if needed.

**For recipients**

1. Download the `.dmg`, open it, drag TypeByVoice to Applications.
2. First launch: right-click TypeByVoice → **Open** (Gatekeeper blocks unsigned apps).
3. Enable **Microphone** and **Accessibility** when prompted.

Bump `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` in the Xcode target before each share build.

Unit tests live in `TypeByVoiceTests`. Integration tests in
`TypeByVoiceIntegrationTests` start the Node `cli-mock` from
`contracts/dictation-v1` and run the real coordinator + encoder + remote engine
pipeline against it.

## Manual insertion matrix

Do not automate. After a successful dictate, confirm the transcript lands at the
caret in each target, both with and without a clipboard manager running
(e.g. Paste, Maccy, CopyClip).

| Target | Without clipboard manager | With clipboard manager |
|---|---|---|
| TextEdit | | |
| Notes | | |
| VS Code | | |
| Terminal | | |
| Safari text field | | |

For each cell: focus an editable field, dictate a short phrase, verify insert,
then verify the previous clipboard contents are restored after
`clipboardRestoreDelayMs` (default 150 ms). Note any app that only keeps the
transcript on the clipboard (fallback path) instead of pasting.
